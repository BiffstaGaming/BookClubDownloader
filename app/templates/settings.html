Encoding speed & CPU
Books that are already AAC (.m4b/.m4a) are joined without re-encoding — that takes seconds. MP3 books have to be encoded; these settings decide how much work that is. The log of each book shows how long it took (e.g. 11h 32m of audio in 3m 10s).
CPU cores (this machine has {{ cpu_cores }})
The encoder always runs at low priority so other services stay responsive. Limiting cores keeps the CPU cooler; the book takes longer. Blank = all cores.
Files of a multi-file book encoded at the same time — the main speed/heat trade-off. Each job keeps about one core busy, so jobs = cores you allow is the fastest; fewer is cooler. Capped at the core limit.
and
E.g. 01:00 and 07:00 to encode overnight. Books that only need copying or joining (seconds of work) are never held back. Leave both empty for any time. A book already encoding finishes.
